# Plan: OpenAI SDK Migration

spec: _specs/openai-sdk-migration.md

## Summary

Remove CrewAI entirely from the project and replace it with a thin, direct OpenAI API/SDK integration. The CrewAI crew currently in the codebase (`TripPlanner` in `crew.py`, its YAML agent/task config, and the `train`/`replay`/`test`/`run_with_trigger` CLI helpers built around it) is still the unmodified project scaffold — it is not wired into any real business logic (venue search/lookup runs entirely through `serper_places.py`/`serper_lookup.py`/`venue_processing.py`, none of which call CrewAI). So this migration has two parts: (1) delete every CrewAI-specific file, dependency, config entry, and CLI helper that has no direct OpenAI SDK equivalent, and (2) add a small, direct OpenAI SDK client helper — using the single model already configured via `MODEL` in `.env` — so future AI-driven capabilities have a straightforward, framework-free way to call OpenAI. No existing business behavior changes as a result.

## Assumptions

- Per the spec's answered Open Questions: the OpenAI SDK is called directly (no in-house agent/task/crew-style abstraction is introduced); only one model is used, read from the existing `MODEL` environment variable in `.env` (already present, alongside `OPENAI_API_KEY`); no CrewAI-specific feature (structured/pydantic outputs, multi-step task chaining) needs a specific replacement since nothing in the current codebase relies on those; and the CrewAI-oriented CLI commands (`train`, `replay`, `test`, `run_with_trigger`) are dropped entirely since they have no direct OpenAI SDK equivalent.
- Because the existing `TripPlanner` crew (`researcher`/`reporting_analyst` agents, `research_task`/`reporting_task` tasks) is unused scaffold with no callers anywhere in `trip_planner.py` or `venue_processing.py`, "reimplementing every capability that ran through CrewAI" reduces to: providing a general-purpose OpenAI SDK client helper that any future capability can call directly, rather than porting a specific agent/task pipeline one-for-one — there is no functional pipeline to port.
- `src/trip_planner/tools/custom_tool.py` (a `crewai.tools.BaseTool` scaffold subclass) is deleted along with the rest of the CrewAI scaffold, since it imports directly from `crewai` and is not used anywhere; there is no equivalent "custom tool" concept needed yet for direct OpenAI SDK calls.
- `AGENTS.md` is a CrewAI-specific reference document (auto-generated by `crewai create`, explicitly about CrewAI's API) and is removed, since it no longer describes anything in this codebase. `CLAUDE.md`'s instruction to read `AGENTS.md` before writing CrewAI code is removed along with it.
- `main.py`'s `run()` function already does not invoke the CrewAI crew (the `TripPlanner().crew().kickoff(...)` call is commented out and unused) — it only calls `create_itinerary(travel_info)`. That function and its `trip_planner`/`run_crew` script entries are kept; only the `import` of `TripPlanner` and the leftover unused `inputs`/commented-out line are cleaned up.
- Historical spec/plan documents under `_specs/` and `_plans/` that mention CrewAI (e.g. `concurrent-venue-processing.md`, `serper-places-search.md`) are left untouched — they're records of past work, not living documentation, and updating them is out of this migration's scope.

## Files to Change

- `pyproject.toml` — remove the `crewai[tools]==1.15.6` dependency and add an `openai` dependency; remove the `[tool.crewai]` section; remove the `train`, `replay`, `test`, and `run_with_trigger` entries from `[project.scripts]` (no OpenAI equivalent); keep `trip_planner` and `run_crew` pointing at `trip_planner.main:run`.
- `src/trip_planner/crew.py` — delete. The `TripPlanner` `@CrewBase` class and its agent/task/crew methods have no OpenAI SDK equivalent needed right now.
- `src/trip_planner/config/agents.yaml` — delete. CrewAI YAML agent configuration no longer applies.
- `src/trip_planner/config/tasks.yaml` — delete. CrewAI YAML task configuration no longer applies.
- `src/trip_planner/config/` (directory) — remove if left empty after the above deletions.
- `src/trip_planner/tools/custom_tool.py` and `src/trip_planner/tools/__init__.py` — delete. CrewAI `BaseTool` scaffold with no callers.
- `src/trip_planner/openai_client.py` (new) — a small module exposing a configured OpenAI SDK client (reading `OPENAI_API_KEY` and `MODEL` from the environment) for future AI-driven capabilities to call directly.
- `src/trip_planner/main.py` — remove the `TripPlanner` import, the `train()`, `replay()`, `test()`, and `run_with_trigger()` functions (and their now-unused `topic`/`current_year`/trigger-payload input dicts), and the leftover commented-out crew kickoff line in `run()`; keep `run()`'s `TravelInfo`/`create_itinerary` logic as-is.
- `AGENTS.md` — delete. This file is a CrewAI-specific reference doc that no longer matches the project.
- `CLAUDE.md` — update the Project Overview, Commands, and Architecture sections to remove CrewAI-specific guidance (the `AGENTS.md` pointer, `crew.py`/YAML config descriptions, `crewai run`/`crewai test`/etc. commands) and describe the direct OpenAI SDK approach instead (the new `openai_client.py` helper, the `MODEL`/`OPENAI_API_KEY` env vars, and the simplified `main.py` entry points).
- `README.md` — replace the CrewAI-branded installation/usage instructions with instructions matching the OpenAI SDK-based project (no more `crewai install`/`crewai run`, no more references to `crewai.com`/CrewAI docs/Discord).
- `tests/` — no existing test currently imports `crew.py`, CrewAI, or the removed `main.py` functions (verified by search), so no test file needs to change to keep passing; a new test file (e.g. `tests/test_openai_client.py`) is added to cover the new client helper.

## Implementation Steps

1. Add the `openai` package as a dependency in `pyproject.toml` (via `uv add openai` or an equivalent manual edit + `uv sync`), and remove the `crewai[tools]==1.15.6` dependency and the `[tool.crewai]` section.
2. Create `src/trip_planner/openai_client.py`: read `OPENAI_API_KEY` and `MODEL` from the environment (raising a clear error if either is missing, mirroring the existing `SERPER_API_KEY` check pattern in `serper_places.py`), and expose a small function/helper that returns a configured OpenAI SDK client (and/or a thin wrapper function for making a direct chat/completions call with the configured model) for future callers.
3. Delete `src/trip_planner/crew.py`, `src/trip_planner/config/agents.yaml`, `src/trip_planner/config/tasks.yaml`, and the `config/` directory if now empty.
4. Delete `src/trip_planner/tools/custom_tool.py` and `src/trip_planner/tools/__init__.py`, and the `tools/` directory if now empty.
5. Update `src/trip_planner/main.py`: remove the `from trip_planner.crew import TripPlanner` import; delete the `train()`, `replay()`, `test()`, and `run_with_trigger()` functions; remove the unused `inputs = {'topic': ..., 'current_year': ...}` dict and the commented-out `#TripPlanner().crew().kickoff(inputs=inputs)` line from `run()`, leaving it to build `TravelInfo` and call `create_itinerary` directly.
6. Update `pyproject.toml`'s `[project.scripts]` to remove the `train`, `replay`, `test`, and `run_with_trigger` entries (since their backing functions no longer exist), keeping `trip_planner` and `run_crew`.
7. Delete `AGENTS.md`.
8. Update `CLAUDE.md`: remove the "Before writing or modifying any CrewAI code, read `AGENTS.md`" instruction and other CrewAI-specific framing in the Project Overview; rewrite the Commands section to drop `crewai run`/`crewai test`/`crewai train`/`crewai replay`/`crewai log-tasks-outputs` in favor of however the project is now run (e.g. `uv run trip_planner` or the equivalent script entry); update the Architecture section to remove mentions of `crew.py`/`config/agents.yaml`/`config/tasks.yaml` and document `openai_client.py` and the `MODEL`/`OPENAI_API_KEY` environment variables instead.
9. Update `README.md` to describe the project without CrewAI branding: installation via `uv sync`, running via the project's script entry point, and configuring `.env` with `OPENAI_API_KEY`/`MODEL`/`SERPER_API_KEY`, removing crewAI-specific links and terminology.
10. Add `tests/test_openai_client.py` covering the new client helper: builds a client using `OPENAI_API_KEY`/`MODEL` from the environment, and raises a clear error when required environment variables are missing — mirroring the mocking approach already used in `tests/test_serper_places.py`.
11. Run `uv sync` (to drop the CrewAI dependency and add `openai`) and `uv run pytest` to confirm the full test suite still passes with no CrewAI dependency installed.

## Testing

- New unit tests in `tests/test_openai_client.py` verifying the OpenAI client helper reads `OPENAI_API_KEY`/`MODEL` correctly and fails clearly when they're missing, mocking the OpenAI SDK boundary so no real API calls are made.
- Run the full existing test suite (`uv run pytest`) after the migration to confirm no regressions — no current test depends on CrewAI, so this is mainly a confirmation that removing `crew.py`/config/tools didn't break any import elsewhere.
- Manually run the project's entry point (e.g. `uv run trip_planner`) to confirm `main.py`'s `run()` still executes `create_itinerary` correctly after the CrewAI-related code is stripped out.

## Risks / Open Questions

- Removing `train`/`replay`/`test`/`run_with_trigger` drops CrewAI AMP-oriented workflows (training, replay-by-task-id, trigger payloads) with no replacement, per the spec's answered Open Question ("drop if necessary"). If any external tooling or documentation still references `uv run train`/`replay`/`test`/`run_with_trigger`, those references will need cleanup beyond this codebase.
- The new `openai_client.py` is intentionally minimal (a direct client/call wrapper) since no concrete AI-driven capability is being (re)built in this migration — the spec's Out of Scope excludes new AI-driven features. The first real caller of this helper will likely surface additional needs (e.g. structured output handling) that aren't addressed here.
- Deleting `config/` and `tools/` directories assumes nothing else in the project references them (confirmed via search for `crewai`/`crew` across the repo); worth a final grep for `agents_config`/`tasks_config`/`custom_tool` before deleting, in case something was missed.
