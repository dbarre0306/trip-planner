# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project overview

A CrewAI-based multi-agent project (`crewai[tools]==1.15.6`, Python >=3.10,<3.14, managed with `uv`). The crew currently in place (`researcher` + `reporting_analyst` agents, `research_task` + `reporting_task` tasks) is still the unmodified scaffold generated by `crewai create crew` — the agents/tasks/topic have not yet been customized for actual trip planning. When implementing trip-planning behavior, expect to rewrite `config/agents.yaml`, `config/tasks.yaml`, and the inputs in `main.py` rather than extend the existing research/report agents in place.

**Before writing or modifying any CrewAI code, read `AGENTS.md` in the repo root.** It documents the exact `1.15.6` API (agents, tasks, crews, flows, tools, memory, knowledge, deployment) and explicitly warns that training data on CrewAI is likely stale. Follow the patterns there — e.g. always use `crewai.LLM` (never `ChatOpenAI`), always add `# type: ignore[index]` on `self.agents_config[...]` / `self.tasks_config[...]` access, and keep agent/task method names matching their YAML keys exactly.

## Commands

```bash
uv sync                              # install/sync dependencies
crewai run                           # run the crew (entry point: trip_planner.main:run)
crewai test -n 5 -m gpt-4o-mini      # test the crew over N iterations against a model
crewai train -n 5 -f training.json  # train the crew
crewai replay -t <task_id>           # replay from a specific task
crewai log-tasks-outputs             # show latest task outputs
```

There is no test suite yet — `tests/` is empty.

### Environment

`.env` requires `OPENAI_API_KEY` (referenced in README) and currently sets `MODEL=gpt-4o-mini`. Add other provider keys (e.g. `ANTHROPIC_API_KEY`, `SERPER_API_KEY`) here as tools/LLMs are added.

## Architecture

- `src/trip_planner/crew.py` — the `@CrewBase` `TripPlanner` class. `@agent` and `@task` decorated methods build `Agent`/`Task` objects from the YAML configs; the `@crew` method assembles them into a `Crew` with `Process.sequential`.
- `src/trip_planner/config/agents.yaml` / `config/tasks.yaml` — declarative agent and task definitions (role/goal/backstory, description/expected_output/agent). This is the primary place to define new agents and tasks; keep `crew.py` minimal per the YAML-first convention in `AGENTS.md`.
- `src/trip_planner/main.py` — local entry points (`run`, `train`, `replay`, `test`, `run_with_trigger`), each building an `inputs` dict (currently `topic` / `current_year`) and calling `TripPlanner().crew().kickoff(...)`. Keep this file free of business logic — it exists only to drive local execution.
- `src/trip_planner/tools/custom_tool.py` — placeholder `BaseTool` subclass to model custom tools on; attach real tools to agents (not tasks) unless a task needs a tool override.
- `knowledge/user_preference.txt` — sample knowledge source content; not currently wired into any agent/crew via `knowledge_sources`.
- `pyproject.toml` — `[project.scripts]` defines the CLI entry points above; `[tool.crewai]` marks this as a `"crew"` project (not a `"flow"`) for `crewai run` and AMP deployment.
